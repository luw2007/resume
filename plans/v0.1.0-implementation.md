# Resume v0.1.0 implementation plan

## Objective

Build and release `resume`, a read-only Rust launcher that discovers Codex, Claude Code, Pi, and OMP Sessions in a directory-derived Scope, lets the user fuzzy-filter and preview them through embedded Skim, then replaces itself with the selected agent's exact native Resume command from the persisted Session Workspace.

## Evidence and decisions

Read before implementation:

- [`CONTEXT.md`](../CONTEXT.md): canonical product language and Scope rules.
- [`docs/adr/0001-rust-and-skim-for-terminal-session-picker.md`](../docs/adr/0001-rust-and-skim-for-terminal-session-picker.md): accepted Rust/Skim boundary.
- [`docs/research/session-formats.md`](../docs/research/session-formats.md): sanitized, version-specific evidence for the four first-party integrations.

The four integrations remain independent. Shared code may normalize paths/text, stream JSONL safely, represent presentation data, and launch a process, but must not impose a shared transcript schema.

## Non-negotiable invariants

1. Discovery and Preview never modify an agent file, database, configuration, mtime, directory entry, or index. The native agent may write only after the user selects Resume.
2. A rendered Skim row is never identity or launch state. Selection returns an opaque key into an in-memory Session map.
3. Session identity includes agent plus isolation provenance (effective data root, profile/session root where applicable) plus the integration-owned native locator. The resumable ID is a separate field.
4. Workspace is persisted Session data. Encoded storage paths do not replace it. Resume rechecks and enters that Workspace immediately before `exec`.
5. Launch uses discrete program/argv/environment values and never a shell.
6. JSONL parsers tolerate unknown records and a partial final line, isolate per-file errors, impose size bounds, and never repair or migrate.
7. Activity is positive-evidence-only. Failure to prove Active yields Unknown, not Inactive.
8. An incomplete integration remains Discover Only or Planned; `v0.1.0` requires all four first-batch integrations to pass exact Resume contract tests and local read-only validation.

## Dependency graph

```text
Step 0: repository bootstrap
  ├─ Step 1: core model, config, CLI, Scope
  ├─ Step 2: Skim feasibility gate
  └─ Step 3: safe readers, text, Preview foundation

Steps 1 + 3

  └─ Step 6: Codex JSONL integration

Steps 1 + 3 + 4
  └─ Step 7: OMP integration

Step 6
  └─ Step 8: optional Codex SQLite enrichment

Steps 0–9

```

Steps 4, 5, and 6 can proceed in parallel after the shared foundations stabilize. Step 7 follows Pi only to reuse proven JSONL primitives, not Pi format assumptions. Step 8 must not block Codex discovery.

## Step 1 — Model identity, launch provenance, configuration, CLI, and Scope

### Context

The largest correctness risk is resuming the wrong Session due to ID collisions or directory overmatching. Implement pure, tested semantics before any transcript adapter or UI.

### Work

Define first-class types:

```text
SessionKey       = integration-owned opaque identity including effective root/profile/native locator
Session          = key + metadata + workspace evidence + support/activity/risk status
ResumeSpec       = program + argv + cwd + narrowly scoped environment overrides
WorkspaceEvidence = recorded/inferred/unknown plus optional historical Git identity
IntegrationError / Diagnostic = redacted category, count, optional verbose path/error chain
```

- Preserve paths and argv as `PathBuf`/`OsString`; do not force lossy UTF-8 into launch state.
- Parse CLI with Clap:
  - optional `DIRECTORY`;
  - mutually exclusive `-U/--up <N|all>` and `-D/--down <N|all>`;
  - repeatable `-a/--agent` replacing configured agents;
  - `--since <duration|date|all>`;
  - `--list`, `--json`, `--verbose`, `--config`;
  - `--confirm-always`, `--no-confirm`;
  - `config example`; `completions bash|zsh|fish`.
- Implement strict TOML at `--config`, then `$XDG_CONFIG_HOME/resume/config.toml`, then `~/.config/resume/config.toml`; reject unknown/invalid fields. Supported fields are agents, since, confirm_always, preview hidden/visible, preview_position auto/right/bottom, verbose.
- Implement Scope as pure membership logic over canonical real paths:
  - no explicit direction + Git available: identify Git common directory and enumerate `git worktree list --porcelain`; match Sessions whose Workspace lies at any depth inside one of those worktrees, excluding a distinct nested repository;
  - no explicit direction outside Git or Git failure: exact base directory only, warning on Git failure;
  - explicit up: exact current real directory and its N ancestors only;
  - explicit down: current real directory plus descendants within N real component edges;
  - `all`, root, symlink, missing path, `--up 0`, `--down 0` exactly as `CONTEXT.md` states.
- Treat `$HOME` and `/` Workspaces as Broad Workspace risks.
- Define deterministic final ordering: activity descending, unknown last, stable key tie-break.

### Tests

- Table-driven Scope matrix for Git/main worktree/linked worktree/nested repo/non-Git/symlink/up/down/all/root/missing Workspace.
- CLI conflict and exit-code tests.
- Strict config precedence tests.
- Identity collision tests across agent/root/profile/native locator.
- Non-UTF-8 path and argv tests on Unix.

### Exit criteria

- Scope has no filesystem-recursive scan.
- Rendered text cannot be used to retrieve or launch a Session.
- Pure tests exhaust the confirmed directory examples and adversarial cases.

## Step 2 — Embedded Skim feasibility gate

### Context

Skim is accepted only if its public library API meets the launcher's essential interaction model without a fork or a second TUI. This step is a throwaway-capable spike and blocks full picker implementation.

### Work

Build a minimal prototype proving:

- Session-like candidates can be streamed from a bounded channel while the picker is open.
- Each custom `SkimItem` separates safe `display`, searchable `text`, and opaque `output`.
- Preview content is supplied from an in-memory key lookup and scrolls with native Skim behavior.
- Preview starts hidden and `Ctrl+O` toggles it.
- `Ctrl+R` can switch Normalized/Raw and refresh, or the accepted fallback can render both sections without rebuilding the picker.
- Selection remains tied to opaque identity while candidates arrive; document actual behavior if Skim cannot safely reorder/update emitted items.
- Esc, Ctrl+C, empty input, zero results, resize, panic, and normal selection restore the terminal.
- `/dev/tty` operation works when stdin is redirected; no control terminal and terminal smaller than 60×10 fail before picker start.
- Candidate and Preview content is protected against ANSI/OSC/control-sequence execution.

Use a bounded producer channel and cooperative cancellation. Do not build Active modal, adapter logic, or polished row layout in this spike.

### Decision gate

Pass: keep Skim and codify the exact supported interactions in tests.

Fail: stop implementation and revisit ADR 0001 with the user. Do not silently add Ratatui, fork Skim, or weaken exact selection/terminal-restoration guarantees.

### Verification

Automated PTY tests plus a controlled manual tmux smoke test on macOS. Add Linux PTY coverage in CI once available.

## Step 3 — Safe JSONL, text normalization, Preview, diagnostics, and cancellation foundation

### Context

All four integrations read untrusted, possibly live files. Shared helpers may provide mechanics, never agent schemas.

### Work

- Implement a streaming JSONL reader that:
  - has configurable line/file/record bounds and bounded JSON nesting;
  - retains valid records;
  - treats a malformed final unterminated line as incomplete;
  - reports malformed middle records without aborting unrelated files;
  - accepts unknown records for adapter-specific dispatch;
  - never opens files for write or follows a session-file symlink outside the effective configured root.
- Implement terminal-safe text normalization:
  - strip/encode ANSI, CSI, OSC 8/52, title/clipboard controls, C0/C1, and bidi controls;
  - preserve ordinary Unicode;
  - fold list newlines/tabs to spaces;
  - render Raw as semantically unfiltered but still terminal-safe.
- Implement source-first, structure-fallback injection filtering. Only collapse complete known wrappers such as injected `<skill>...</skill>`; never delete arbitrary XML.
- Model user messages and attachments. Never render base64; Normalized attachment output uses safe placeholders.
- Build deterministic summaries with 1 MiB bounded early read, Unicode display-width truncation, explicit slash-command/automated-message filtering delegated to integrations.
- Build a process-only Preview cache: 64 MiB LRU, 16 MiB per item, explicit truncation notice and source path, no disk cache.
- Implement redacted diagnostics and `--verbose`; never log message bodies or sensitive remotes/URLs.
- Implement bounded channels, one discovery worker per integration, maximum four Preview workers, cooperative cancellation, and 250 ms ordinary-exit join budget.
- Add read-only regression helpers that snapshot bytes, mtimes, and directory entries around discovery/Preview.

### Tests

Malformed/partial/live-growing JSONL; huge lines/messages; ANSI/OSC/bidi attacks; genuine XML that must remain; known skill injection; text/image/file attachments; cache eviction; cancellation/backpressure; read-only snapshots.

### Exit criteria

- No helper assumes a common header position or event schema.
- Fuzz/property tests cannot cause terminal escape emission or unbounded allocation within configured limits.

## Step 4 — Pi integration

### Context

Evidence: Pi 0.84.1, root `PI_CODING_AGENT_DIR` or `~/.pi/agent`, effective session root precedence includes `PI_CODING_AGENT_SESSION_DIR` and settings, JSONL v1-v3, authoritative header `id`/`cwd`. Safest exact Resume is by absolute JSONL path.

### Work

- Resolve effective Pi agent/session roots without invoking Pi in an opening/migrating mode.
- Support default grouped and custom flat roots; always filter by header `cwd` through Scope.
- Parse v1/v2/v3 headers read-only and extract stable ID, Workspace, parent, name, creation/activity times, real user messages, and attachment placeholders.
- Use latest `session_info.name`; otherwise summary from first valid human input.
- Implement integration-local dedupe. Key includes effective session root and canonical transcript locator, not just header ID.
- Generate `ResumeSpec` using `pi --session <absolute-jsonl-path>` and preserve custom `--session-dir`; never use `--session-id`.
- Treat Session Control as Active evidence only after a validated stable-ID/path association; otherwise Unknown.

### Tests

Use the complete Pi fixture matrix in the research document. Fake `pi` must capture exact cwd/argv/env. Assert discovery/Preview does not migrate v1/v2 files or change any byte/mtime.

### Exit criteria

Pi is marked Supported only after exact path Resume, alternate root behavior, and missing Workspace gating pass.

## Step 5 — Claude Code integration

### Context

Evidence: Claude Code 2.1.220, root `CLAUDE_CONFIG_DIR` or `~/.claude`, heterogeneous top-level JSONL under `projects`, collision-prone workspace directory encoding, UUID filename plus embedded `sessionId`, authoritative event `cwd`.

### Work

- Scan only valid top-level Session transcripts, excluding nested subagent artifacts as independent Sessions.
- Never reverse workspace-key directory names. Parse and Scope-match recorded `cwd`.
- Accept stable identity only when UUID filename and embedded Session ID agree; otherwise diagnose/skip or Discover Only according to available evidence.
- Extract user string/text blocks; exclude `tool_result`, assistant, system, and injected records.
- Title precedence: explicit agent/display name, then AI title, then deterministic user summary. If native behavior remains unproven, document this as Resume presentation rather than claiming native picker equivalence.
- Generate `claude --resume <uuid>` with Workspace as child cwd and preserve nondefault `CLAUDE_CONFIG_DIR`.
- Keep activity Unknown absent future positive correlation.

### Tests

Workspace-key collision pair, UUID agreement/disagreement, title variants, heterogeneous producer versions, unknown events, tool-only input, truncated/malformed records, alternate root, missing Workspace, fake `claude` launch contract.

### Exit criteria

No Workspace is inferred from directory encoding; exact-ID Resume and root propagation are proven.

## Step 6 — Codex JSONL integration

### Context

Evidence: Codex 0.146.0, root `CODEX_HOME` or `~/.codex`, authoritative rollouts in dated JSONL directories, stable `session_meta.payload.id`, Workspace `payload.cwd`, exact `codex -C <cwd> resume <uuid>`.

### Work

- Discover active and archived rollout roots without depending on SQLite or legacy indexes.
- Parse `session_meta`; use embedded ID and Workspace, not filename or `payload.session_id`.
- Extract and deduplicate paired `event_msg.user_message` and `response_item` user representations; support attachment placeholders and exclude developer/system injections.
- Preserve source/import/thread metadata only as safe badges; never display repository remote or import source path by default.
- Key includes effective `CODEX_HOME` and canonical rollout/native ID.
- Generate `codex -C <workspace> resume <uuid>` and preserve alternate `CODEX_HOME`.
- Optional Activity evidence: live Codex process + open FD for exact rollout. Report as possible/Active with confidence and PID/TTY; absence is Unknown.

### Tests

Modern/older/archived/imported/noninteractive shapes, ID/filename mismatch, alternate root, duplicate representation, unknown records, missing Workspace, malformed/truncated files, fake exact argv/env.

### Exit criteria

Codex discovery works with state DB and indexes absent, stale, or corrupt.

## Step 7 — OMP integration

### Context

OMP has the highest isolation risk. Evidence: OMP 17.2.10; `PI_CONFIG_DIR` base; default and named profile agent roots; named profile selection ignores unprofiled `PI_CODING_AGENT_DIR`; optional XDG split roots; v1 title record before v3 Session header; imports get new OMP IDs.

### Work

- Implement OMP-specific root resolution for default profile, named profiles, profile environment precedence, unprofiled override, custom session directory, and fixture-proven XDG behavior.
- Discover named profiles automatically. Profile/effective roots are part of Session identity.
- Parse past permitted title sidecar records to the v3 header. Never reuse Pi's header-position assumptions.
- Resolve effective title across header/title/title_change state; extract only user-attributed messages and safe attachment placeholders.
- Parse `foreign_session_import` into a safe source badge while retaining the new OMP header ID as resumable identity. Never merge it with origin Codex/Claude Session.
- Generate default or `--profile <name>` exact Resume args, add `--session-dir` when required, preserve the root environment, and use header Workspace.
- Correlate Active only with live process + TTY + matching terminal breadcrumb Session path. Stale marker alone is Unknown.

### Tests

Full OMP fixture matrix from research, especially duplicate IDs across profiles, base/profile/root environment interactions, imported source/new IDs, title-before-header, stale/live breadcrumbs, and fake launch provenance.

### Exit criteria

No profile/root collision can select or launch a Session from another isolation boundary.

## Step 8 — Optional Codex SQLite enrichment

### Context

`state_5.sqlite` can improve titles, activity, preview, Git/archive metadata, but is derived and evolving. It must never be required for discovery.

### Work

- Open via read-only URI `mode=ro` with short busy timeout. Do not use `immutable=1` on a live WAL database; do not migrate, checkpoint, or issue write PRAGMAs.
- Detect schema/column availability instead of assuming a fixed version.
- Join by native thread ID and validate rollout path/Workspace before enriching.
- Establish precedence: rollout ID/Workspace remain authoritative; DB title/times may enrich; disagreement produces a diagnostic rather than replacing identity.
- DB absent, locked, corrupt, stale, schema-changed, or unsupported degrades silently to JSONL plus a summary warning.

### Tests

Absent DB, locked/busy, WAL activity, old/new schema, corrupt DB, stale row, missing rollout, timestamp disagreement, and read-only filesystem snapshots.

### Exit criteria

Deleting the DB does not change which valid Codex JSONL Sessions are discoverable or resumable.

## Step 9 — Production picker, confirmation, revalidation, and exec

### Context

Skim owns list/filter/preview interaction. Risk confirmation happens after Skim exits. The launcher must not auto-select or auto-resume a sole result.

### Work

- Feed immutable Session items through the proven bounded Skim path. Integrations sort locally by activity; global order may be approximate while streaming. Only perform final reorder if the prototype proved selection stability.
- Row priority: `STATUS AGENT[PROFILE] UPDATED TITLE BRANCH WORKSPACE`; retain status/agent/time, truncate other columns by Unicode width, keep full fields in search/Preview.
- Preview hidden by default; `Ctrl+O` toggles; auto right/bottom around 60%; `Ctrl+R` uses the proven switch or accepted dual-section fallback.
- Candidate matching includes metadata immediately and user input only when Skim can safely update an item. Do not rebuild and jump selection merely for transcript indexing.
- Handle unsupported candidates: remain in Picker with reason if public API permits; otherwise exit 2 with reason.
- After selection, cancel producers, restore terminal, retrieve structured Session by opaque key, and revalidate transcript identity, CLI availability, Workspace, support status, and risk evidence.
- Confirm Active, Workspace changed, conflicting metadata, Broad Workspace, or global confirm-always. `--no-confirm` cannot bypass risk prompts.
- Use Unix `CommandExt::exec` with discrete program/argv and narrowly scoped environment overrides. On error, print diagnostic and exit 1; do not reopen Picker.
- Exit semantics: Esc 0, Ctrl+C 130, no Sessions 0, all integrations failed 1, invalid CLI/config 2, refused risk 0.

### Tests

PTY behavior; immutable selection; late candidate arrivals; unavailable selection fallback; normal/risk confirmation; CLI disappearing; Workspace deletion/replacement; transcript identity change; fake agents capturing cwd/argv/env; terminal restoration on success path helper, error, cancellation, and panic.

### Exit criteria

No code path can execute a display string or use a stale row index as selection.

## Step 10 — CI, fuzzing, and read-only adversarial matrix

### Work

- GitHub Actions on Ubuntu and macOS:
  - `cargo fmt --check`;
  - `cargo clippy --all-targets --all-features --locked -- -D warnings`;
  - `cargo test --all-features --locked`;
  - Rust 1.91 MSRV build;
  - `cargo deny check licenses bans advisories sources`.
- Add parser fuzz/property targets for JSONL, terminal text, Scope paths, and duration/config parsing. Bound runtime and memory.
- Add PTY tests for Skim Ctrl+O/Ctrl+R, Ctrl+C, resize, empty results, redirection via `/dev/tty`, control sequences, and restoration.
- Add concurrent-writer tests for JSONL and Codex WAL without touching real homes.
- CI must replace HOME/XDG/agent roots with temporary fixtures and fake executables.
- Add periodic/release builds for four targets:
  - `aarch64-apple-darwin`;
  - `x86_64-apple-darwin`;
  - `aarch64-unknown-linux-musl`;
  - `x86_64-unknown-linux-musl`.
- If musl is blocked by audited dependencies, document evidence and validate selected GNU glibc floor before changing targets.

### Exit criteria

No test reads the runner's real agent directories or credentials. Read-only snapshot tests pass for every adapter.

## Step 12 — Release v0.1.0 and Homebrew tap

### Preconditions

- All four first-batch agents are Supported.
- macOS and Linux CI, PTY suite, fake launch contracts, local read-only validation, and fixture privacy review pass.
- Dependencies and licenses are reviewed; lockfile is current; Changelog is dated and frozen.
- Remote repository and tap token permissions are explicitly authorized and configured.

### Work

- Tag `v0.1.0` from protected main.
- GitHub Actions builds target artifacts, publishes SHA-256 files, and creates GitHub artifact attestations.
- Release artifacts use stable version/OS/architecture names.
- A fine-grained personal access token, scoped only to `luw2007/homebrew-tap` with `Contents: Read and write`, updates `Formula/resume.rb` with version-specific artifact URLs/checksums and shell completions.
- Formula smoke tests run `resume --version` and `resume --help`; a separate controlled smoke verifies Picker startup where a TTY is available.
- Tap update failure is independently retryable and never causes rebuilding/re-tagging the same release.
- Preserve developer installation via `cargo install --git https://github.com/luw2007/resume`; do not publish crates.io in v0.1.0.

### Exit criteria

```bash
brew install luw2007/tap/resume
resume --version
```

works on supported artifacts, and the Formula checksum matches the attested GitHub Release artifact.

## Plan mutation protocol

- A parser-format discovery may update only its integration step and research evidence unless it changes the shared model.
- A change to Session identity, Scope, Resume safety, or Skim feasibility requires revisiting dependent steps before implementation continues.
- If an integration cannot prove exact Resume, mark it Discover Only and do not release v0.1.0 under the current completion gate; either fix it or explicitly renegotiate the release gate.
- If Skim fails Step 2, stop and supersede ADR 0001 before building a different TUI.
- Never “solve” a format mismatch by invoking an agent to migrate/repair a real Session during discovery.

## Explicit non-goals for v0.1.0

- Windows support.
- Machine-wide Session listing.
- Project-level configuration.
- Dynamic plugin packages or agent installation.
- Session modification, repair, deletion, import, merge, or cross-agent deduplication.
- Continuous filesystem watching or refresh.
- External pager/editor, custom Skim fork, direct Ratatui UI, or persistent Preview/search cache.
- Cursor, OpenCode, Grok, or Gemini integration; these remain later independent work.
